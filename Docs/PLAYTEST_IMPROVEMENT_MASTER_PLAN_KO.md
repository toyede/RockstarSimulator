# Raccoon Roll 플레이 테스트 개선 마스터플랜

작성: 2026-10-08 · 기준 브랜치: `sub-developing` · 기준 커밋: `83a889e`

이 문서는 구현 계획이다. 아래 작업은 아직 실행하지 않았다. 코드 조사에서 확인한 내용과 플레이로 다시 확인할 내용을 구분한다.

## 1. 두 작업 묶음과 목표

| 묶음 | 포함 범위 | 완료 시 기대하는 상태 |
|---|---|---|
| A — 1·2번 | 표시 오류 해결 + 화면 배치·가독성 정리 | 어떤 스테이지에서도 필요한 UI가 보이고, 일시정지·결과 화면이 정상적으로 전환된다. |
| B — 3·4번 | 관객 관찰·튜토리얼·대사 개선 + 카드·관객·사운드 연출 | 무엇을 보고 카드를 선택해야 하는지 이해하고, 선택의 결과를 눈과 귀로 확인할 수 있다. |

진행 순서: **A 수정 → A 검증·기준 화면 고정 → B 핵심 경험 → B 연출 → 통합 검증**.

2026-10-08 추가: 스테이지 조명은 `STAGE_LIGHTING_IMPLEMENTATION_PLAN_KO.md`로 별도 계획했다. LUX//FAUNA는 마젠타·시안 EDM 쇼(레이저·LED·스모그)로 정리하며, 조명 구현 시 L5 통합 검증까지 기준 화면을 고정한 뒤 B를 진행한다. 정확한 음악 박자 동기화(L6)는 B의 필수 선행 조건이 아니다. 이번 추가는 계획이며 조명/B 실행 완료를 뜻하지 않는다. 디버그는 현재 복구된 상태를 유지한다.

B의 대사 작성·큐시트 시안·사운드 후보 준비는 A와 병행할 수 있다. 같은 씬·프리팹을 수정하는 구현 작업은 A 인계 이후 진행한다.

이번 범위에서 덱·증강 효과·점수 공식·보스 미션 조건을 새로 설계하지 않는다. 조명 힌트 축소와 튜토리얼 단축은 비교 플레이로 효과를 확인한 후 적용한다.

## 2. 현재 구조에서 확인한 출발점

| 항목 | 코드에서 확인한 사실 | 계획에 반영할 점 |
|---|---|---|
| 보스 타이머 | `BossStagePresentation.hideTimerHud` 기본값이 true. `HideScoreHud()`도 타이머를 숨긴다. | 타이머를 숨기는 두 경로와 씬 설정을 함께 확인한다. |

| 일시정지 UI | 보스 UI의 런타임 Canvas order는 155. 블러 Canvas는 소속 Canvas order−1로 배치된다. | 실제 Pause Canvas order와 런타임 Canvas를 수집해 앞뒤 순서를 비교한다. 원인 확정 전 일괄 숫자 변경 금지. |
| 디버그 | `TourDebugInput`, `DebugForceGameOverInput` 등은 에디터·개발 빌드에서 동작한다. | 정식 빌드 제외뿐 아니라 평소 투어 플레이에서 안내·버튼이 안 보이게 한다. |
| 스테이지 배치 | `StageSet`에 공연장별 소품·조명 참조가 있다. | 기존 세트 안에서 수동 배치를 조정하고 GUID·참조를 유지한다. |

| 맵 이동 | `TourMapView.MoveBusTo()`는 이미 `Vector2.Lerp`로 선형 이동한다. | 새 이동 시스템 대신 가속·감속과 작은 도착 연출을 추가한다. |

조사 시작 시 아트 `.meta` 8개에 기존 변경이 있었다. 구현 착수 시 다시 git status를 확인하고 해당 변경을 보존한다. 이 문서 작성에서는 게임 파일을 수정하지 않았다.

## 4. 작업 B — 핵심 경험과 연출 개선

### B0. 문구·화면 콘셉트 먼저 확정

구현 전에 세 가지 작은 산출물을 준비한다.

- **대사표:** 기존 대사 / 수정 대사 / 표정 / 효과음 / 강조할 행동.
- **큐시트 시안:** 튜토리얼·이벤트·보스 미션 공통 스타일. 제목, 행동, 진행, 성공·실패를 구분.
- **연출표:** 카드/상황별 대상, 움직임, 색, 효과음, 반복 제한.

AI 큐시트 초안은 지면·클립·선·장식용 이미지로 제작한다. 행동 설명과 숫자는 Unity 텍스트로 분리한다. A에서 확정한 위치·텍스트 영역을 기준으로 디자인한다.

### B1. 관객 관찰의 재미 검증

문제 가설: 후반에는 조명 색과 미션 문구가 정답에 가까운 정보를 주어 관객을 보지 않아도 선택할 수 있다.

작업:

1. 현재 버전으로 후반 공연을 플레이하고 카드 선택의 근거가 관객·조명·미션 중 무엇인지 기록한다.
2. 관객의 복장·호응 단계·반응 애니메이션이 실제로 구분되는지 먼저 확인한다.
3. 기존 성향 조명과 성향을 직접 알려주지 않는 분위기 조명을 비교한다. 후자는 기존 Hype 기반 프리셋을 우선 활용한다.
4. 설명 없이 관객을 읽기 어려우면 Hover/길게 누르기의 힌트를 유지하고 관객 표현을 보강한다.
5. 비교 플레이에서 판단이 가능하고 재미가 좋아졌을 때 후반 힌트 강도를 단계적으로 줄인다.

완료 기준: 플레이어가 “이 관객의 복장/상태를 보고 이 카드를 골랐다”고 설명할 수 있다. 힌트 감소로 무엇을 해야 할지 모르는 시간이 늘면 원안으로 복구한다.

조명 제거는 이 단계의 확정 사양이 아니다. 정전·Fever·특별 관객 플래시와 일반 조명 힌트를 구분해서 유지한다.

### B2. 체험형 튜토리얼로 압축

대상: `TutorialFlow`, `TutorialOverlayUI`, `TutorialDragGuideUI`, `TutorialTips`.

추천 흐름:

| 체험 | 화면 설명 | 통과 조건 |
|---|---|---|
| 관객 취향 | 한 문장 소개 → 관객과 카드 제시 | 복장을 보고 맞는 카드 사용. 세 성향을 짧게 경험. |
| 관객의 마음 | 지루한 관객을 보여주고 Hover/길게 누르기 안내 | 대사를 실제로 읽고 맞는 행동 사용. |
| 여러 관객 반응 | 서로 다른 관객에게 카드 한 장 사용 | 반응의 차이와 전체 합을 확인. |
| 콤보·Fever | 전체 반응이 양수일 때 콤보가 이어진다는 짧은 안내 | Fever에서 카드 한 장 사용. |
| 짧은 실전 | 기존 10초·1,000점 미니 공연 | 성공 시 본 공연, 실패 시 미니 공연 재도전. |

작업 원칙:

- 같은 규칙을 여러 설명 화면으로 반복하지 않는다. 한 화면은 한 행동만 안내한다.
- Special 교육은 현재처럼 Stage 2에서 처음 필요할 때 진행한다.
- 새 관객·말풍선 관찰 단계는 필요한 읽기 시간을 확보한다. 기존 2초 관찰 기준을 유지한다.
- 잘못된 카드 복귀, 필수 카드 보장, 자동 Fever 차단, 스킵, 모바일 입력을 보존한다.
- 게임오버 조건은 실제 조건과 일치하는 짧은 문장으로 안내한다.
- 첫 플레이 기록을 기존 저장 키와 연결한다. 기존 유저에게 모든 교육을 강제로 다시 띄우지 않는다.

완료 기준: 처음 하는 사람이 관객과 카드를 연결하고, 손패를 직접 사용해 공연을 시작할 수 있다. 설명 클릭 수와 필수 체험 시간을 기록해 기존보다 단축됐는지 확인한다.

### B3. 밴드 대사와 감정·장면 연출

대상: `DialogueSequence`, `DialogueLine`, `DialoguePortraitCatalog`, `DialoguePanel`.

대사 규칙: 대상·상황·행동을 명확히 쓴다. 음악 용어는 실제 행동을 떠올리게 하는 경우에 사용하고 한 대사에 과하게 몰아넣지 않는다.

수정 예:

- 기존: “그쪽 부분을 빼라는데?”
- 수정: “사장님이 두 번째 후렴 뒤 기타 솔로를 줄여 달래. 공연 시간이 밀렸대.”

작업:

1. 인트로·스테이지 사이·보스·엔딩 대사를 대사표로 검수한다.
2. 곡 제목이 필요하면 실제 사용하는 곡명 또는 팀이 정한 밴드 곡명을 확정해서 쓴다.
3. 너구리 표정은 기존 `emotionId`와 카탈로그를 이용한다. 없는 표정은 아트 요청 목록으로 남긴다.
4. Stage 2 “펑!”은 해당 줄 시작 시 효과음·짧은 플래시/충격·일러스트를 함께 재생한다.
5. 기존 `sfxId`를 먼저 활용하고, 화면 효과가 필요할 때만 해당 줄의 최소 연출 지정과 표시 담당을 추가한다.
6. 빠른 클릭·스킵·씬 전환에서 화면 효과와 소리가 중복되거나 남지 않게 한다.

완료 기준: “그쪽”, “그 부분” 같은 표현 없이 대사만 읽어도 무엇을 이야기하는지 이해한다. 펑 연출은 한 번만 발생하며 스킵 후 정리된다.

### B4. 신문 기사와 결과 보상 연출

대상: `ResultNewspaperCatalog`, `ResultHeadlineSelector`, `ResultNewspaperView`, `PerformanceReport`.

작업:

1. 공연장·성공/실패·등급별 헤드라인을 짧고 개성 있게 작성한다.
2. 기사에는 실제 기록에서 두드러진 사실 하나를 골라 쓴다. 없던 사건·반응·관객 수는 만들지 않는다.
3. 실제 성공/실패를 우선하고, 점수가 높다는 이유로 실패 결과를 성공처럼 쓰지 않는다.
4. A에서 확정한 폰트·줄 수를 준수한다.
5. 기존 도장 효과음 연결과 등장 타이밍을 확인하고 필요하면 짧은 종이 펼침 소리를 더한다.

문구 톤 예시:

- 골목 성공: “지나가던 발걸음, 너구리 앞에서 멈췄다!”
- 골목 실패: “왕관은 월드스타… 관객은 다음 버스 탔다”
- 보스 승리: “LUX//FAUNA의 팬들, 너구리 무대로 넘어왔다”

완료 기준: 제목이 성적과 어울리고 후기에서 이번 공연의 특징을 알 수 있다. 효과음은 클릭으로 연출을 넘겨도 겹쳐 재생되지 않는다.

### B5. 관객 입퇴장·카드별 집단 반응

대상: `AudienceRosterPresenter`, `AudienceMemberActor`, 기존 절차 움직임·풀·입퇴장 연출.

순서: **입퇴장 정리 → 모쉬핏 한 장 시연 → 나머지 대표 카드 확장**.

작업:

1. 생성 시 입장 위치→객석, 퇴장 시 객석→통로로 이동하도록 기존 경로를 개선한다.
2. 보스 팬 쟁탈은 양쪽 무대 방향을 따르는 이동으로 표현한다. 카메라 왕복과 겹쳐도 위치가 튀지 않게 한다.
3. 동시에 여러 명이 이동하면 출발 타이밍·속도를 조금씩 다르게 한다.
4. 기본 자리 배치, 평소 흔들림, 카드 반응 오프셋을 합성한다. 각 연출이 transform을 덮어쓰며 싸우지 않게 한다.
5. `모쉬핏 열어!`의 긍정 반응 관객은 양옆으로 벌어졌다가 중앙으로 모인다. 부정 반응 관객은 별도 소극적 반응으로 구분한다.
6. 마이크 넘기기는 함께 손 들기/박자 반응, Chill 계열은 작은 흔들림 등 대표 행동부터 구현한다.
7. 반응 중 Hover 영역·특별 관객 카드 드롭 판정이 실제 표시와 일치하는지 확인한다.

완료 기준: 카드 행동의 의미가 관객 움직임에서 보인다. 연속 카드 사용·퇴장·풀 재사용 후 잔여 오프셋이 없다. 논리 인원·점수·미션 결과는 기존 이벤트가 결정한다.

### B6. 카드·맵·시계·사운드 보강

| 작업 | 구현 방향 | 완료 기준 |
|---|---|---|
| 카드 추가 | `CardHandUI`의 기존 Draw/Reroll 연출을 확인하고 일반 손패 보충에 짧은 팝/빛 추가. 카드 인스턴스를 기준으로 신규 카드만 강조. | 초기 손패·일반 보충·증강 Draw·Reroll에서 한 번씩만 발생. 드래그를 방해하지 않음. |
| 맵 이동 | 기존 `MoveBusTo()`의 선형 t를 가속·감속 곡선으로 변경. 작은 흔들림·출발 먼지·도착 팝 적용. | 정확히 노드에 도착하고 기존 완료 콜백이 한 번 호출됨. 이동 중 화면 전환에도 잔여 효과 없음. |
| 시계 긴박감 | 남은 15초/5초 구간에 작은 펄스·빨간 틴트 적용하는 초안. 시간 연장 VFX와 충돌하지 않게 표현을 합성/우선 처리. | 시간이 다시 늘어나면 경고 해제. Pause·Fever·보스 미션을 방해하지 않음. |
| 카드 효과음 | 카드 행동별 짧은 스트럼·리프·떼창/박수 등 지정. 기존 사운드 ID와 Mixer Group 재사용. | 카드의 행동이 귀로 구분되고 BGM·미션 경고를 가리지 않음. |
| 커서 VFX | 짧고 성긴 픽셀 잔상. 기존 카드 트레일과 같은 팔레트 사용. | 버튼·말풍선·카드를 가리지 않음. 화면 밖 복귀 시 긴 선이 생기지 않음. |

BGM 가속은 별도 실험 항목이다. 현재 곡과 연출의 박자·피치에 영향을 줄 수 있으므로 시계 펄스·틴트부터 확인한 뒤 도입한다. 모바일에서는 커서 잔상 대신 터치 피드백 적용 여부를 검토한다.

## 5. 책임과 파일 충돌 관리

팀 역할은 기존 분담을 기준으로 한 작업 제안이다.

| 영역 | 민영 | 우용 | 윤빈 |
|---|---|---|---|
| A 화면 안정화 | 재현·UI 전환·배치·검증 | 최신 시계/카드 연출 연결 확인 | 공연장·UI 에셋 의도 확인 |
| B 핵심 경험 | 관객 힌트·튜토리얼·스토리·기사 | 카드/증강 조건과 설명의 일치 확인 | 관객 상태 가독성·감정/큐시트 아트 |
| B 연출 | 맵·다이얼로그·관객 이동 연결 | 카드 VFX·카드 효과음·시계 연출 협업 | 관객 동작·일러스트·UI 에셋 |

공동 수정 파일의 인계 규칙:

- Main 씬: A에서 배치 확정 → B가 그 배치를 기반으로 연출 연결.
- `PerformanceTimerUI`: A는 표시 복구, B는 펄스/틴트. 우용의 시간 연장 VFX를 먼저 확인.
- `StageLightController`/Bridge: A는 크기·각도·위치, B는 성향 힌트 정책.
- `ResultNewspaperView`: A는 중복·폰트·레이아웃, B는 기사·사운드.
- `CardHandUI`: 기존 증강 VFX를 보존하고 추가 연출만 연결. 덱/증강 계산은 우용 담당.
- Setup 메뉴: 전체 재생성 대신 대상 컴포넌트·참조만 변경. 수동 레이아웃을 덮어쓰지 않는다.

## 6. 구현·검증 단위

| 차수 | 구현 단위 | 확인한 뒤 넘어갈 조건 |
|---|---|---|
| A-1 | 디버그·타이머·Pause·결과 중복 | 일반/보스 화면 전환이 정상 |
| A-2 | 공연장 에셋·조명 배치·결과 폰트 | 공연장별 기준 화면 확보 |
| B-1 | 큐시트·대사·기사 초안, 관객 힌트 비교 | 문구·정보 순서·힌트 정책 결정 |
| B-2 | 체험형 튜토리얼·구체적인 대사·신문 후기 | 처음 하는 사람이 규칙을 이해 |
| B-3 | 입퇴장·모쉬핏·대표 카드 반응·효과음 | 한 카드의 의미가 시청각으로 전달 |
| B-4 | 맵·시계·카드 추가·커서 연출 | 연출이 읽기와 조작을 방해하지 않음 |
| 통합 | Title→Stage 1→결과→증강→맵→Stage 2, 보스→결과→엔딩 | 루프·입력·오디오·복구 검증 완료 |

각 차수는 작은 변경 묶음으로 검증하고 기록한다. 코드 변경 후 Unity 컴파일·Console을 확인하고, UI 변경은 Game View에서 직접 확인한다. 릴리즈 빌드 확인과 개발 빌드 확인을 구분한다.

## 7. 시간이 부족할 때의 범위

**먼저 완료:** A 전체, 짧은 체험형 교육, 이해되는 미션·대사, 자연스러운 관객 입퇴장, 대표 카드 한 장의 차별화 연출.

**그다음:** 큐시트 최종 아트, 신문 기사 다양화, 카드 추가·시계·맵 연출과 카드별 사운드 확장.

**마지막:** 커서 트레일, 모든 카드의 전용 집단 애니메이션, BGM BPM 가속.

현재 바로 시작할 작업은 **A0 재현 기록 → A1~A4 화면 표시 문제 해결**이다. A 기준 화면이 정해지면 A5~A6와 B의 문구·아트 준비를 연결한다.
