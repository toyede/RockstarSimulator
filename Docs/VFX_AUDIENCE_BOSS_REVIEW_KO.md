# VFX · 보스 드랍 · 관객 행동 개선안

2026-10-08 / 코드·프리팹 조사 기반 개선안 / **구현 반영 완료**

구현 결과와 실제 검증 범위는 [구현·검증 보고서](VFX_AUDIENCE_BOSS_IMPLEMENTATION_REPORT_KO.md)를 참고한다.
아래의 '현재 상태', '발견한 문제'는 구현 전 조사 기록이고, '제안' 수치는 당시 튜닝 초안이다.

## 1. 이번 작업의 목표

이펙트를 많이 추가하는 것이 아니라, **무슨 일이 일어났는지 / 카드가 누구에게 통했는지** 보이게 만든다.
기존 피버 연출, 카드 판정·점수, 증강 효과, Rank·게이지의 수동 배치는 유지한다.
아래 수치 중 '제안'은 튜닝 시작점이지 확정 밸런스가 아니다.

## 2. 필요한 VFX와 우선순위

| 우선 | 항목 | 현재 상태 | 작업 방향 |
| --- | --- | --- | --- |
| P0 | 관객 호응도 바 | 채움 계산은 정상. Lit 재질과 조명 대상 레이어 불일치 발견 | 먼저 가시성 문제 수정·실제 화면 재검증 |
| P1 | 소나기 | 3스테이지에 규칙·안내는 있으나 비 파티클 없음 | 픽셀 빗줄기 2층 + 최소한의 바닥 물방울 |
| P1 | 빗속 관객 보호 피드백 | Chill 카드가 관객 전체에 호응도 +6을 주는 규칙 존재 | 비를 막았다는 짧은 보호 아치로 규칙 설명 |
| P1 | 카드 보충 | 새 손패에 이미 작은 6개 픽셀 반짝임 존재 | 새 카드 테두리 점등 + 짧은 팝으로 보강 |
| P1 | 카드별 관객 행동 | 모쉬 .45유닛 이동, 일부 카드 작은 바운스 존재 | 모쉬·Chill·Singalong을 서로 다른 몸동작으로 구분 |
| P1 | 보스 드랍 | 예고 중 레이저 개방이 최대, 시작 때 개방값 초기화 | 모으기 → 시작 순간 펼치기 → 유지 → 복귀 |
| P2 | 새 카드 영구 획득 | 손패 보충과 다른 상황 | 보상 화면 카드 → 덱 아이콘으로 이동, 획득 확인 |
| P2 | 보스 관객 쟁탈 | 이동·경로 조명은 있음 | 도착 순간 발밑 작은 파장 + 해당 팀색 픽셀 |

새로 만들 필요가 낮은 항목: 일반 카드 Impact, LOVE/INTERESTED 반응 파티클, 피버 파티클, 특수 카드 대기 효과, 카드 강화 효과, 점수·타이머 UI 픽셀 효과. 관련 컴포넌트가 이미 있으므로 중복 시스템을 만들지 않는다. 커서 효과는 현재 선택 기능이며 우선순위를 올리지 않는다.

## 3. 소나기 — 규칙이 눈에 보이게

### 현재 실제 규칙

- `festival_rain_shower`: 3스테이지 공연 45초에 시작, 12초 동안 진행. 다른 이벤트·특수 관객 요청에 따라 시작이 지연될 수 있다.
- 자연 호응도 감소가 2배가 된다.
- 이벤트 중 Chill 카드가 Weak가 아닌 반응이면 관객 전체 호응도 +6.
- 관객 수를 시작 시점 이상으로 지키면 성공. VFX에서 이 수치를 다시 적용하지 않는다.

### 화면 구성 제안

| 층 | 형태·움직임 | 초기 튜닝값 제안 |
| --- | --- | --- |
| 원경 비 | 가는 흰색·회색 픽셀 선, 살짝 기울어 하강 | 동시 50~80개, 화면상 폭 1~2px, 알파 .12~.22 |
| 전경 비 | 드문 굵은 선, 원경보다 빠름 | 동시 15~25개, 폭 2~3px, 알파 .18~.28 |
| 바닥 물방울 | 객석 바닥에 작은 V자/점 2~3프레임 | 동시 8~12개 이하, .18~.3초 후 소멸 |

- 시작 .3초 동안 밀도 상승. 종료 .4초 동안 방출 감소 후 잔여 입자만 소멸.
- 선 길이는 8~18px부터 조절. 커다란 스모그·화면 전체 파란 오버레이는 사용하지 않는다.
- 전경 비도 카드·말풍선·반응 텍스트·미션 UI 뒤에 둔다. 관객 옷차림이 읽혀야 한다.
- 고정 카메라 기준 월드 영역에 배치. World Simulation Space로 입자가 방출기와 함께 끌려가지 않게 한다.
- 물방울은 정해둔 바닥 영역에서 방출. 파티클 충돌 판정과 실제 관객 물리 계산은 필요 없다.
- 비 종료·스테이지 이탈·결과 전환·컴포넌트 비활성화 시 정리. `StageEventRule.Cancel()`은 결과 이벤트를 내보내지 않으므로 종료 이벤트만 구독해서는 안 된다.

### Chill로 보호했을 때

비가 진행 중이고 실제 보호 조건을 만족한 카드에 한해, 남아 있는 관객 위에 작은 청록색 아치를 .35초 보여준다.
비가 아치 위에서 2~3개의 픽셀로 튀고, 기존 호응도 회복 표시를 함께 사용한다.
피버 금색 효과와 분리하여 'Chill 카드로 비 피해를 버텼다'는 인상을 준다. 텍스트가 필요하면 한 번만 `관객 보호!` 표시.

구현 위치: 별도 `RainShowerVFX`가 기존 이벤트를 읽고 시각만 담당. `RainShowerRule`은 수치·성공 판정을 계속 담당.

## 4. 카드 추가 — 두 상황을 구분

### A. 공연 중 손패가 보충되는 경우

기존 `CardHandUI.SparkleNewCards`를 보강한다.

- 새로 들어온 카드만 테두리 .18초 점등 → .12초 복귀.
- 스케일 1 → 1.06 → 1, 총 .25초. 레이아웃 위치·드래그 판정은 변경하지 않는다.
- 모서리에서 흰색/회색 픽셀 8~12개 방출. 카드 계열색은 소량의 테두리 강조에만 사용.
- Draw는 한 장씩 최대 .06초 차이로 등장. 여러 장이면 '손패가 늘었다'는 방향성이 보여야 한다.
- 기존 Draw/Reroll 전용 연출과 중복 발사하지 않는다. 최초 손패·단순 재배치·같은 카드 재바인딩에는 발사하지 않는다.
- 개별 카드가 같은 종류여도 개수를 기준으로 새 카드를 판별하는 기존 방식 유지.

Overlay UI에는 이미 있는 `UIPixelBurstEmitter`/`AugmentCardVFX`를 재사용한다. 월드 ParticleSystem을 덧붙여 좌표 문제를 재발시키지 않는다.

### B. 증강 보상으로 덱에 새 카드가 영구 추가되는 경우

위 A와 별도 피드백이다. 보상 카드가 살짝 커진 뒤 **덱 아이콘이 있는 경우** 그쪽으로 축소 이동 + 픽셀 10~16개.
덱 아이콘이 없으면 카드 아래 `덱에 추가됨`만 표시하며 가짜 목적지를 만들지 않는다.
UI는 실제 적용 완료 통지만 받는다. 카드 추가·증강 적용·후보 추첨 로직은 우용 담당 구현을 유지한다.

## 5. 관객 행동 — 세 카드가 서로 다른 장면을 만들게

실제 CardCatalog의 카드와 성향을 확인했다: `모쉬핏 열어!` Mosh / `템포 올려!` Chill / `손 머리 위로!` Singalong.
**제약: 신규 관객 애니메이션·팔/손 프레임은 제작하지 않는다. 현재 스프라이트의 이동·회전·미세한 스케일 변화와 기존 VFX만 사용한다.**

| 카드 | 관객 행동 | 보조 VFX | 차별점 |
| --- | --- | --- | --- |
| 모쉬핏 열어! | 좌우로 크게 갈라졌다가 중앙 쪽으로 다시 뛰어듦 | 합류 순간 발밑 먼지·착지 픽셀 | 큰 가로 이동과 덩어리의 합류 |
| 템포 올려! | 제자리에서 두 번 몸을 낮췄다 세우며 박자를 탐 | 발밑 청록 박자 파장 2회 | 작지만 리듬이 분명한 두 박자 |
| 손 머리 위로! | 왼쪽부터 작은 점프가 이어지고 단체로 좌우 스웨이 | 보라 음표 1~2개 | 관객 사이를 타고 흐르는 웨이브 |

### 모쉬핏: 기존 동작을 크게

제안 .9~1.1초: **벌어짐 .25 → 짧은 대기 .1 → 재합류 .2 → 착지·복귀 .35~.55**.
현재 .45유닛인 가로 이동을 최대 .9~1.1유닛부터 튜닝한다. 화면 경계·관객 간격이 좁으면 자동 제한.
재합류 때 .2~.3유닛 점프 + 짧은 스쿼시 + 발밑 먼지 3~5개. 매번 새 카메라 흔들림을 추가하지 않는다.

- 좌우는 반응 참여 관객들의 중앙 X를 기준으로 나눈다. 보스처럼 무대가 이동해도 월드 원점 기준으로 한쪽에 몰리지 않아야 한다.
- 반응 관객 1명만 있으면 제자리 스텝·점프로 대체. 실제 물리 충돌·관객끼리 위치 교환은 하지 않는다.
- 기존 LOVE IT 점프와 겹치면 높이를 더하지 않고 큰 값으로 제한한다.

### Chill: 템포 올려!

제안 .8초. 첫 .1초 준비 → .15초 몸을 낮춤 → .15초 복귀 → 한 번 더 반복.
전체 스프라이트가 발밑 기준으로 3~5도 기울고, 세로 스케일을 최대 4~5%만 줄였다 원래대로 돌아온다. 머리를 따로 움직이거나 박수치는 포즈는 만들지 않는다.
가로 흔들림 .08~.12유닛부터 시작. 평상시 랜덤 흔들림을 잠깐 줄이고 두 박자 타이밍을 맞춘다. 큰 점프는 없다.
청록색 얇은 픽셀 타원 파장을 발밑에 두 번. 점프 난무가 아니라 '박자에 반응했다'는 차이를 만든다.
각 반응 관객의 체형을 유지하며 동일 스프라이트만 변형한다.

### Singalong: 손 머리 위로!

**손을 실제로 올리는 포즈 대신, 따라 하는 군집 반응을 보여준다. 카드 이름·효과는 변경하지 않는다.**
제안 개체당 1초. 짧은 .15~.2유닛 점프 1회 → 좌우로 몸 기울이기 2회 → 원래 자세.
첫 점프는 화면상 왼쪽부터 오른쪽 순서로 .04~.06초 지연. 전체 지연은 .3초 이하로 제한하며, 카메라가 움직이는 보스도 현재 관객 배치를 기준으로 순서를 잡는다.
이후 좌우 스웨이는 공통 기준 시간에 맞춰 같은 방향으로 움직인다. 회전은 6~8도부터 튜닝하고, 가로 이동은 작게 제한한다.
음표 1~2개가 점프 순간 머리 위에서 떠오른다. 추가 손/팔 스프라이트나 새로운 관객 프레임은 필요 없다.
반응 관객이 1명이면 웨이브 대신 작은 점프+스웨이만 재생한다.

### 공통 연결 규칙

- 실제 `AudienceCardReacted`의 개인 반응이 양수인 관객만 성공 동작. 성향만 보고 무조건 모두 춤추게 하지 않는다.
- 현재 `AudienceRosterPresenter → AudienceMemberActor.PlayCardMotion` 흐름을 확장한다.
- 이동은 현재 layout + 입퇴장 + idle + 카드 동작 합성 안에서 처리. 관객 Transform을 서로 다른 코루틴이 덮어쓰지 않는다.
- 겹친 카드 사용은 현재 오프셋에서 자연스럽게 새 동작으로 전환. 퇴장 시작 시 카드 행동 취소, 풀 반환 시 초기화.
- 큰 카드 동작 중 idle 점프를 줄여 동작을 읽을 수 있게 한다. 말풍선·Hover Collider는 실제 움직이는 관객을 따라간다.
- 회전·스쿼시는 발밑 기준으로 보정하고 최대 5% 수준의 변형을 사용한다. 경고 바·반응 텍스트는 본체가 기울어도 수평을 유지하도록 표시 앵커를 분리한다.
- 점수·호응도·보스 관객 쟁탈 판정은 변경하지 않는다. 연출 때문에 관객이 생기거나 사라지지 않아야 한다.

## 6. 보스 드랍 — 양보다 타이밍을 고친다

### 코드에서 확인한 구조적 문제

1. `StageLightingRig`의 레이저 개방값 `opening`은 **드랍 예고 중에만** 상승한다.
2. 예고 끝에는 `peakLasers=8`, 미션 시작에는 개방값이 0이 되고 `dropLasers=6`으로 줄어든다. 터져야 할 순간 오히려 닫힐 수 있다.
3. 조명은 독립적인 sin 파형으로 움직인다. 실제 음악의 박자·드랍을 분석하여 맞추는 구조는 아니다.
4. 상대 조명만 약해지는 동안 다른 워시·우리 무대 조명이 그대로면 화면 전체의 '직전 정적' 대비가 약하다.
5. Revenge도 레이저 6개를 유지하므로 드랍만의 특별한 모습이 줄어든다.

이는 코드 기반 연출 진단이다. 이번에는 실제 플레이 화면의 불만 장면을 다시 촬영해 비교하지 않았다.

### 제안 타임라인

| 시점 | 조명 | 파티클·시각 | 지켜야 할 점 |
| --- | --- | --- | --- |
| 평상시 | 시안/마젠타 2~4개가 질서 있게 교대 스윕 | 기존 소량 스모그 | 현재 좋아진 기본 조명 유지 |
| 예고 초반 | 좁은 빔·낮은 LED, 스윕 정지 | 추가 방출 멈춤 | UI·관객은 여전히 읽혀야 함 |
| 예고 마지막 .4초 | 빔을 중앙에 모으고 LED가 중앙으로 수렴 | 낮은 바닥 스모그 준비 | **아직 펼치지 않는다** |
| 패턴 시작 0~.12초 | 레이저 최대 8개를 부채꼴로 펼침, 짧은 청백색 중심 강조 | 양쪽 스모그 1회 + 디지털 픽셀 12~20개 | 전체 화면 흰색 플래시 금지 |
| 시작 .12~.6초 | 넓게 펼친 상태에서 밝기를 한 번 낮췄다 복귀 | 방출 종료, 잔여 입자만 소멸 | 연속 스트로브 대신 한 번의 악센트 |
| 미션 진행 | 6개 내외, 좌우 뱅크가 규칙적으로 교대 | 기존 저밀도 스모그 | 카드·관객 판독이 우선 |
| 해결·중단 | .35초 동안 현재 각도에서 평상시로 복귀 | 잔여 정리 | 레이저 각도 순간 점프 금지 |

색은 LUX//FAUNA의 시안/마젠타 유지. 스모그는 흰색/회색 베이스에 아주 약한 색만 입힌다.
예고 중 입력이 잠긴 구간에서만 전체 월드 밝기를 살짝 낮추며, 미션 시작 시 원래 밝기로 복원한다.
피버·정전·결과 전환·Pause가 겹치면 기존 우선순위를 지키고 중복 플래시를 억제한다. 피버 자체의 금색 연출은 수정하지 않는다.

### 구현 경계

- `StageShowDirector`가 기존 `BossPatternAnnounced / BossLightingHoldProgress / BossPatternStarted / BossPatternResolved`로 Quiet→Charge→Impact→Sustain→Recover 상태를 관리.
- `StageLightingRig`는 받은 단계·진행률을 그림으로 표현. 밝기·각도를 둘 이상의 컴포넌트가 동시에 수정하지 않는다.
- 레이저는 현재 Mesh 기반 `PixelLaserRenderer` 유지. 여러 줄이 정렬되는 레이저는 파티클로 교체하는 것보다 기존 각도 제어가 적합하다.
- 파티클은 스모그·드랍 스파크·디지털 먼지에 한정. 레이저 숫자만 늘리거나 RGB를 랜덤 변경하지 않는다.
- DROP 미션 시작 이벤트 동기화가 1차 목표. **실제 BGM 드랍과 동기화**는 곡별 cue 시각을 따로 지정해야 하며, BPM 가정을 넣어 자동으로 맞았다고 판단하지 않는다.
- 기존 미션 시간·성공 조건·카드 잠금·보스 체력·UI 배치는 건드리지 않는다.

## 6-1. 보스 화면 전환: 보는 쪽 관객은 원색, 반대쪽은 검은 틴트

**추가 확정 요구사항: 보스 관객은 카메라가 보스 무대를 볼 때 원래 색으로 복원하고 무대 조명을 받는다. 이때 우리 관객은 검은 틴트로 전환한다. 돌아오면 반대로 복원한다.**

| 보는 화면 | 너구리 밴드 관객 | 보스 관객 |
| --- | --- | --- |
| 우리 무대 | 원래 색 + 조명 | 검은 틴트 |
| 보스 무대 | 검은 틴트 | 원래 색 + 조명 |
| 이동 중 | 카메라 이동 진행률에 맞춰 자연스럽게 교차 전환 | 반대 방향으로 교차 전환 |

### 현재 확인된 연결점

- `RivalStagePlaceholder.CreateFan()`은 원래 색 대신 `fanTint`를 BaseColor에 저장하므로, 원색과 보기용 틴트를 분리해야 한다.
- `AudienceMemberActor.TryGetIdleVisual()`은 보스 팬에게 빌려주는 애니메이션을 현재 Calm으로 고정한다.
- `BossCameraDirector.CurrentZone`은 팬 이동이 끝난 후 변경된다. 이 값만 확인하면 틴트도 이동 끝에 갑자기 바뀌므로 이동 진행률을 연출에 전달한다.
- 우리 관객 색은 `AudienceMemberActor.ApplyTransform()`이 매 프레임 갱신한다. 밖에서 Renderer.color를 한 번 바꾸는 방식은 사용하지 않는다.

### 구현 계획

1. 카메라 담당이 현재 무대와 이동 진행률을 전달한다. 직접 엿보기, 입장 프리뷰, 패턴 예고, 강제 복귀 모두 같은 전환 경로를 사용한다.
2. 원래 색을 보관하고, 원색 × 보기용 틴트 × 입퇴장 alpha를 최종 합성한다. 보스의 Walk 코루틴이 저장한 어두운 색을 다시 덮어쓰지 않도록 색상 적용 지점을 하나로 둔다.
3. 우리 관객은 보기용 어둡기 값을 개별 액터의 렌더링 합성에 반영한다. 정전용 전역 `SilhouetteBlend`를 카메라 선택 상태로 재사용하지 않는다.
4. 보스 관객에도 기존 관객과 호환되는 Lit 재질을 명시하고, 보스 관객의 Sorting Layer가 Light2D 대상에 포함되는지 확인한다. 월드 빔/워시도 관객 위로 정상 적용되게 한다. 관객 바에 제안한 Unlit 처리를 관객 본체에 적용하지 않는다.
5. 틴트는 RGB만 어둡게 하며 임의로 투명하게 만들지 않는다. 개별 입퇴장 fade는 그대로 보존한다.
6. 스테이지 종료·재시작·연출 중단·SnapHome 시 우리 쪽 원색 상태로 복귀. 정전·피버가 겹쳤다가 끝나도 현재 보는 쪽을 기준으로 복원한다.

## 6-2. 보스 관객 상태: 개별 체력 없이 보스 HP를 공유 기준으로

현재 보스 게이지는 `BossFanBalanceChanged.RivalRatio = Rival / Total`을 사용한다. **새 HP를 만들지 않고 이 기존 게이지의 비율을 관객 상태에도 사용한다.** UI의 보간된 fillAmount가 아닌 룰 이벤트의 실제 비율을 읽는다.

| 보스 HP 비율 — 초기 기준 제안 | 보스 관객 공통 상태 | 기존 아트/Transform 표현 |
| --- | --- | --- |
| 66% 초과 | Hype (코드의 Excited) | 현재 보유한 높은 흥분 상태 아트 + 큰 바운스·스웨이 |
| 33% 초과 ~ 66% | Mid (코드의 Middle) | 중간 상태 아트 + 리듬감 있는 작은 움직임 |
| 0% 초과 ~ 33% | Calm | 차분한 상태 아트 + 작은 흔들림 |
| 0% | 기존 보스 종료 판정 따름 | 새 상태나 자체 퇴장 판정을 만들지 않음 |

- 비율이 낮아질수록 보스 관객의 열기가 식고, 관객을 되찾아 HP가 회복되면 다시 신난다. 모든 보스 관객이 같은 상태 단계이며, 시작 위상·회전·점프 시점에만 작은 편차를 준다.
- 필요한 기존 상태 아트가 없으면 현재 스프라이트 그대로 이동·회전·미세 스케일로 표현한다. 신규 관객 애니메이션 프레임은 요구하지 않는다.
- 보스 관객의 개별 HP·Engagement·자연 감소·개별 체력바는 **사용하지 않는다**. `AudienceRosterSystem`에 가짜 관객으로 등록하지도 않는다.
- 상태 변화는 `BossFanBalanceChanged`에서 계산한다. 임계값을 넘지 않았다면 애니메이션을 매 이벤트마다 처음부터 재생하지 않는다.
- HP로 상태가 바뀌어도 기존 종족·성향·자리·이동 연출은 유지한다. 화면 밖에서도 상태를 갱신해 보스 화면으로 이동했을 때 바로 최신 상태를 보여준다.
- 우리 관객은 기존 개인 호응도 기반 상태를 유지한다. 화면을 옮기는 것은 색 표시만 바꾸며, 우리 관객의 체력·판정·퇴장을 변경하지 않는다.

완료 조건: 양쪽 화면 왕복·팬 이동 중 틴트 전환·HP 상승/감소·각 경계값·정전/피버 종료·중단 복귀를 실제 플레이에서 검증한다. 틴트나 상태 연출만으로 팬 수·보스 HP가 변해서는 안 된다.

## 7. 호응도 바 버그 조사

### 확인된 사실

현재 바는 전체 체력이 아니라 **Calm 단계의 이탈 경고 바**다. 호응도 0보다 크고 Calm일 때만 표시하며, 비율은 `Engagement / 33`이다.

연결된 Unity Editor에서 프리팹을 임시 로드하여 Awake와 표시 계산을 검사했다. 저장·씬 변경·Play Mode 진입은 하지 않았다.

| 호응도 | 계산된 채움 | 채움 월드 폭(기본 크기) |
| --- | --- | --- |
| 33 | 100% | 1.15 |
| 32 | 97% | 1.12 |
| 25 | 76% | .87 |
| 15 | 45% | .52 |
| 5 | 15% | .17 |
| 1 | 3% | .03 |

감소 즉시 비율이 0이 되는 문제는 이 검사에서 재현되지 않았다. 모든 검사에서 채움 alpha=1, 바 활성화=true.

대신 다음 불일치를 확인했다.

- 바 프리팹의 Background/Fill은 `Sprite-Lit-Default` 재질.
- 런타임 `SetLayout`은 바를 `Effects` Sorting Layer에 배치.
- 저장된 Main의 일반 좌우·전역 Light2D는 Default만 대상으로 설정.
- Effects를 대상으로 포함한 조명은 현재 피버 Spotlight이며 초기 강도 0.

따라서 **채움은 존재하지만 조명 때문에 검게 보이는 현상**이 유력 원인이다. 실제 게임에서 같은 장면을 재현한 최종 확정은 아직 하지 않았다.

### 수정 계획

1. 바의 Background/Fill에만 공통 Sprite-Unlit 재질을 적용. 캐릭터·무대의 Lit 재질과 조명 설정은 그대로 둔다.
2. Effects에서 조명보다 위, Hover·반응 텍스트를 가리지 않는 현재 정렬을 유지.
3. 표시 비율과 기준은 그대로 유지. 호응도를 임의로 회복시키거나 모든 관객의 바를 항상 표시하는 규칙 변경은 하지 않는다.
4. 아주 낮은 양수 값은 실제 화면의 픽셀 정렬을 검사. 필요할 경우 최소 1px 표현만 보장하되 실제 수치는 바꾸지 않는다.
5. 풀 재사용·회복·단계 변경·퇴장 시 활성화와 채움 상태도 함께 검사.

Unlit은 경고 UI를 읽게 하는 처리다. 정전 때 이 바도 숨길지는 별도 정책이며, 재질 변경만으로 정전 미션의 의도를 바꾸지 않는다.

## 8. 필요한 신규 에셋 최소 목록

| 에셋 | 규격 초안 | 용도 |
| --- | --- | --- |
| Rain_Streak | 4×16, 2종, 투명 PNG | 얇은/굵은 픽셀 비 |
| Rain_Splash | 12×8, 3프레임 | 바닥 물방울 |

먼지·음표·픽셀·파장은 기존 반응 VFX 아틀라스/메시를 우선 사용한다. 새로운 풀스크린 텍스처, 고해상도 노이즈, 레이저 전용 신규 아트는 우선 필요 없다.
관객 행동용 신규 스프라이트·프레임은 0개다. 위 비·보호 VFX 후보는 관객 애니메이션과 별개이며, 절차적 픽셀 메시로 대체하면 이미지 에셋 없이도 구현할 수 있다.
신규 픽셀 이미지: Point Filter, Mipmap 끔, 기존 아트와 동일한 기준 PPU, 흐린 외곽선 금지.

## 9. 구현 순서와 완료 조건

1. **바 가시성 수정** → Main 실제 플레이에서 자연 감소/카드 감소/회복, 일반 조명·피버·정전 비교.
2. **소나기 + 보호 피드백** → 3스테이지 이벤트 강제 시작·정상 종료·도중 종료·재시작. 카드·UI 가리지 않고 이벤트 종료 후 잔류 없음.
3. **세 카드 관객 동작** → 반응 양수/0/음수, 관객 1명/여러 명, 연속 사용, 보스 좌표, 입퇴장, Hover 추적.
4. **보스 드랍 타이밍 수정** → 예고 마지막이 아닌 시작 순간이 최대 개방. 첫/강화 드랍, Revenge, 피버 겹침, Pause·중단 복귀.
5. **손패 보충 보강** → Draw/Reroll/같은 종류 여러 장/초기 손패/드래그 중 추가. 기존 전용 연출과 중복 없음.
6. 실제 WebGL·모바일에서 확인. 총 입자 수는 제한하며 전체 화면 알파 오버드로우·프레임 시간은 측정 후 판단한다. Editor 수치 검사로 WebGL 성능을 보증하지 않는다.
