## 3. 모든 스테이지의 네 조명 층

| 층 | 역할 | 제어 주체 / 원칙 |
|---|---|---|
| 기본 가독성 | 관객 복장·표정, 밴드 윤곽 | 낮은 중성 기본광. 일반 성공/실패마다 흔들지 않음 |
| 성향 힌트 | 기존 관객 최다 성향의 보조 정보 | 기존 Bridge 판정 유지. 객석 가까운 작은 영역에 제한 |
| 공연장 테마 | 벽, 천장등, 트러스, LED, 바닥 가장자리 | 새 StageLightingRig. 색은 장소/아티스트 정체성 |
| 상황 큐 | Fever, 요청, 정전, 보스 예고·팬 이동 | 기존 이벤트를 받아 해당 그룹만 일시적으로 변경 |

현재 두 빔을 테마와 힌트가 동시에 제어하게 하지 않는다. 첫 적용 때 기존 Light를 어느 층에 남길지 명시하고, 새 Rig의 Renderer 참조와 중복되는지 검사한다. Global Light는 한 주체만 소유한다.

|---|---|---|---|
| 1 골목 | 기존 가로등·상점 불빛 + 작은 시안 무대광 | 피버 때 창문 순차 점등 | 추가하지 않음 |
| 2 지하홀 | 낮은 천장 직하광 3개 + 빨간 뒤 벽 + 역광 2개 | 특별 요청 후광 / 피버 역광 | 필수 아님 |
| 3 페스티벌 | 보라 객석 워시 + 넓은 부채꼴 빔 | 피버 부채꼴 펼침 / 기존 비·깃발 룰 연동 | 기본은 없음 |
| 4 생방송 | 고정 백색 면광원 + 청회색 LED + 작은 ON AIR | 전광판 강조 / 기존 정전 진입·복구 | 추가하지 않음 |

지하홀은 짧고 밀도 높은 빛, 방송국은 고정되고 반듯한 빛, 보스는 정밀하게 움직이는 빛으로 구분한다. ‘각 스테이지마다 같은 X자 빔에 색만 변경’하는 형태로 끝내지 않는다.

## 5. LUX//FAUNA 배치 명세

라이벌 무대 기준 로컬 좌표로 배치한다. 아래 수치는 초기 개수 상한이며 실제 화면·성능 측정 후 조정한다.

| 그룹 | 배치 / 초기 개수 | 화면에서 보이는 행동 |
|---|---|---|
| 넓은 빔 | 기존 좌우 트러스에서 1개씩, 총 2 | 시안·마젠타가 서로 다른 위상으로 교차. 기본 왕복 약 3~5초 |
| 얇은 레이저 | 트러스 상단 2개 + 단상 양끝 2개, 드롭 전용 2개 추가. 최대 6 | 천장 쪽 훑기, 평행 사선, 부채꼴. 빠르되 카메라/UI를 가로지르지 않음 |
| LED | 후면/단상 가장자리 8~12 구역 | 스캔·체이스·기하학 배열. 작은 구역을 순서대로 활성화 |
| 스모그 | 단상 양끝 분출구 2개 | 0.4~0.7초 방출 후 2~3초 동안 낮게 퍼져 사라짐 |
| 바닥등 | 두 무대 사이의 기존 이동 방향을 나타내는 고정 구역 | 팬 영입은 위→아래, 팬 상실은 아래→위 체이스 |

### 움직임 규칙

- 넓은 빔은 큰 호를 부드럽게 스윕한다. 레이저는 더 빠른 작은 호/각도 프리셋을 사용한다.
- 각도·속도·위상을 전부 랜덤하게 바꾸지 않는다. `스캔 → 교차 → 부채꼴 → 복귀`의 짧은 구절을 반복한다.
- 큐 전환은 일반적으로 0.2~0.4초 보간. 목표 각도로 순간이동하거나 매 프레임 방향을 난수로 뽑지 않는다.
- 광원 위치, 빔 폭, 레이저 끝점을 같은 월드 픽셀 격자에 맞춘다. 이동은 부드럽고 윤곽은 계단 형태로 보이게 한다.
- 작은 LED 체이스는 구역당 약 0.12~0.18초 간격부터 검토한다. 많은 구역이 동시에 완전히 꺼졌다 켜지는 반복 스트로브로 만들지 않는다.
- 저점멸 옵션에서는 짧은 on/off를 밝기 보간으로 대체하고 빔 움직임은 남긴다. 이 설정만으로 광과민 안전성을 보장한다고 표현하지 않는다.

### 스모그 규칙

- 투명 배경의 흰색/회색 픽셀 연기 텍스처 1종. 색은 빛으로 약하게 가산하며 연기 자체는 진한 마젠타 덩어리로 만들지 않는다.
- 월드 기준 StageSet/라이벌 앵커 아래에 둔다. 기존 카메라 자식 먼지 루트를 그대로 이용하지 않는다.
- 분출은 위로 조금 솟은 뒤 옆으로 확산. 생성 위치·크기·수명에 작은 편차만 준다.
- 화면 앞쪽 연기는 바닥 가장자리로 한정. 얼굴·Hover 테두리·관객 반응 텍스트 위에 쌓이지 않게 한다.
- 초기 최대 생존 입자는 전체 20개 이하부터 시작. 평상시 4~8개, 드롭 순간만 증가. 정해진 최소 재분출 간격으로 누적 방지.
- 별도 유체/볼류메트릭/3D 조명 시뮬레이션은 도입하지 않는다. 겹침과 틴트로 2D 인상을 만든다.

## 6. 실제 플레이의 큐 흐름

| 상태 / 기존 신호 | 빔·레이저 | LED·스모그 | 플레이 정보 보호 |
|---|---|---|---|
| 평상시 | 넓은 빔 2개 느린 교차, 레이저 2개만 움직임 | 낮은 LED 체이스, 얇은 잔류 연기 | 우리 관객·손패는 기본 밝기 유지 |
| `BossPatternAnnounced` | 빔이 듀오 쪽으로 모임, 레이저 밀도 감소 | 가장자리에서 중앙으로 모이는 LED | 예고 문구에 새로운 가림막을 추가하지 않음 |
| `BossPatternStarted` | 집중했던 빛이 바깥으로 펼쳐짐 | 짧은 체이스 후 패턴별 기본 상태 | 요구 카드색은 미션/전용 강조에만 표시 |
| B2B / BEATMATCH / GUEST LIST | 각기 사선 응답 / 단계별 펼침 / 요청 관객 후광 | 성공 시 해당 구역 1회 점등 | 조명이 카드 성공을 미리 보장하지 않음 |
| KILL SWITCH | 금지 성향을 전체 조명의 색으로 표현하지 않음 | 미션 표시와 대응하는 LED 구역만 비활성 | 관객 성향 힌트나 복장은 숨기지 않음 |
| DROP 도전 시작 | 좁은 V자 빛이 벌어지고 레이저가 확장 | 스모그 1회 분출, 체이스 속도 상승 | 계속되는 전 화면 플래시 없음 |
| `BossPatternResolved` | 성공: 아래 무대 응답 / 실패: 라이벌 사선 응답 | 0.3~0.5초 짧은 큐 후 현 상태로 복귀 | 실제 팬·점수 결과는 룰이 결정 |
| `BossRevengeChanged` | 마젠타·시안 유지, 교차 속도/활성 개수 상승 | LED 체이스 밀도 상승 | ‘악당 빨간 모드’로 변경하지 않음 |
| `FeverStateChanged` | 아래 우리 무대의 금색 가장자리·백색 역광 | 위 EDM 큐는 별도로 유지 | 기존 Fever 카드 황금 연출·음향과 중복 폭발 방지 |
| `BossFanMoved` | 이동 통로의 짧은 빛만 켜짐 | 방향성 바닥 체이스 | 실제 팬 이동 연출을 빛이 가리지 않음 |
| `BossDrainApplied` | 넓은 빔은 유지 | 라이벌 LED 한 구역 짧은 펄스 | 반복 점수 감소마다 전 화면 플래시 금지 |
| 종료 | 룰의 최종 승패 확정 후 승자 무대 중심광 | 잔류 연기 배출 중단, 짧은 정리 큐 | 팬 0명/패턴 성공을 즉시 승리로 오인시키지 않음 |

`BossFanMoved`에는 개별 팬의 경로 좌표가 없다. 1차 바닥등은 `BossArenaLayout` 앵커 간 방향만 표현한다. B5에서 팬 이동을 다듬을 때 동일 경로를 표시 계층에서 공유해야 ‘관객을 정확히 따라가는 빛’으로 확장할 수 있다.

## 7. 음악과 조명의 동기화

### 1차 — 기능 의존 없이 제작

- 조명 구절은 로컬 쇼 시간으로 재생. 시작/예고/도전/Fever/종료는 기존 EventBus로 맞춘다.
- 미션의 DROP 시점과 실제 음악의 드롭 구간은 현재 동일하다고 가정하지 않는다.
- 짧은 상태 전환과 긴 스윕을 조합해 음악 공연처럼 보이게 하되, 정확한 비트 동기화 구현 완료로 보고하지 않는다.

### 2차 — 곡을 확정한 뒤 선택적으로 추가

- 프로필에 곡 ID·BPM·첫 박자 오프셋만 저장한다. BPM 값을 추측해서 확정하지 않는다.
- 오디오 담당과 확인 후 `AudioManager`에 **활성 BGM의 재생 위치/유효 여부를 읽는 작은 API**만 추가하는 방식을 우선 검토한다. 반사로 private AudioSource를 읽지 않는다.
- BGM source의 `timeSamples / frequency`를 기준으로 실제 재생 위치를 읽는다. 프레임 deltaTime 누적만으로 곡 전체의 박자를 맞추지 않는다.
- 루프, 곡 변경, 크로스페이드, 재시작, Pause/Resume를 검증한다. 재생 위치를 얻지 못하면 1차 큐로 폴백한다.
- 오디오 속도·Pitch·Mixer·곡 재생 조건을 조명 때문에 변경하지 않는다. FFT, 자동 BPM 추정, 신규 오디오 미들웨어는 범위 밖.

| `Assets/Scripts/Lighting/StageLightingProfile.cs` — 신규 SO | 스테이지별 테마색·큐 시간·개수 상한·저점멸 값 | 관객 비율, 점수, 미션 조건 저장 |
| `Assets/Scripts/Lighting/StageLightingRig.cs` — 신규 | 해당 StageSet의 Light·LED·레이저·ParticleSystem 참조, 표시 적용·초기화 | 룰 이벤트 판정 / 게임 상태 전환 |
| `Assets/Scripts/Lighting/StageShowDirector.cs` — 신규 | 기존 이벤트→큐 선택, 상태 합성·우선순위·시간 관리 | 점수 변경·팬 생성/삭제·새 미션 발행 |
| `Assets/Scripts/Lighting/PixelLaserRenderer.cs` — 필요할 때만 신규 | 얇은 픽셀 메쉬/공유 머티리얼 레이저 표현 | 레이저 1개마다 Light2D 생성 |
| `Assets/Scripts/Editor/StageLightingSetup.cs` — 신규 | 기존 세트에 중복 없는 Rig 연결, 누락 참조 진단 | 전체 씬/프리팹 재생성 |

기존 파일은 다음 범위만 필요한 만큼 수정한다.

- `StageLightController`: 기존 Global/힌트 광원 소유권 정리. 기존 StageGeometry와 Stage 1 기본 복원은 보존.
- `RivalStagePlaceholder`: 새 Rig 사용 시 기존 `_led` 점멸/색 변경 경로를 위임하거나 비활성. 듀오·팬 생성/이동은 유지. Rig가 없으면 기존 표시 폴백.
- `FeverPresentation` / `FeverSpotlight`: 실제로 동일 Light를 제어할 때만 연결 분리. 기존 카드 황금색·사운드·점수 효과 유지.
- 필요하면 기존 StageSet 적용 훅에 표시용 프로필 연결만 추가. 새 스테이지 진행 시스템을 만들지 않음.

**한 Renderer에는 한 주체만 값을 쓴다.** Director가 상태를 합성하고 Rig가 최종 값을 적용한다. 부품별 독립 코루틴들이 같은 LED/Light를 경쟁적으로 바꾸지 않는다.

월드 구조 예: `StageSet → LightingRig`; 보스는 `BossArenaLayout.RivalStage 앵커 → LUXLightingRig`. 카메라/Canvas 자식으로 만들지 않는다. UI 트레일 좌표 버그와 같은 화면/월드 좌표 혼용을 피한다.

## 9. 상태 충돌·정리 정책

- 같은 그룹: 종료/무대 비활성 → 실제 정전 → 예고·도전 큐 → 짧은 결과 큐 → 기본 쇼. 상태 종료 때 현재 유효 상태로 복귀하며 과거 색을 무조건 복원하지 않는다.
- Fever와 Revenge는 서로 다른 무대 그룹. 위 라이벌 Revenge가 아래 Fever를 덮어쓰지 않는다.
- 보스 카메라 예고는 공연 타이머가 멈추더라도 연출이 이어져야 한다. 조명 시간을 `PerformanceTimer`에 무조건 종속시키지 않는다.
- 반대로 `GameState.Paused`에서는 큐 보간·점멸·스모그까지 정지. GameOver/Ready/Disable에서는 발광과 입자를 정리하고 재시작 시 기본값으로 초기화.
- BGM이 카메라 예고 중 계속 재생되는지 따로 확인. 음악 시계와 게임 타이머를 같다고 간주하지 않는다.
- OnEnable/OnDisable 구독 대칭. 연출 종료 뒤 지연 콜백이 새 스테이지의 Rig를 건드리지 않게 취소/버전 관리.
- 이벤트가 몰려도 분출/펄스는 횟수·재사용 대기 상한 적용. 매 이벤트 Instantiate/Destroy 금지.
- Rig가 없거나 참조가 비어도 게임은 진행. 누락을 한 번 진단하고 기존 조명 폴백.
- 보스 엿보기 때는 라이벌 쇼를 정상 표시하되, 우리 화면에서는 화면 경계 밖의 레이저가 관객 영역까지 침범하지 않도록 길이·구역 제한.

## 10. 추가 아트와 비용 관리

| 항목 | 1차 프로토타입 | 최종 아트 |
|---|---|---|
| 넓은 픽셀 빔 / 얇은 레이저 | 기존 shader·cookie + 필요 시 얇은 메쉬 | 새 래스터 빔 애니메이션 불필요 |
| EDM 배경·트러스·듀오 | 기존 0930/0918 아트 연결 | 교체보다 배치·발광 분리 우선 |
| LED / 바닥등 | 기존 SquareSprite 기반 구역 | 원하면 픽셀 LED strip로 교체 |
| 스모그 | 흰색/회색 alpha 픽셀 연기 1종 필요 | 32~64px 시작, 실제 축척에 맞춰 조정. Point 필터 / 저밀도 |
| 지하 천장등 | 단순 임시 기구 + 빔 | 천장 기구 1종 필요 |
| 방송 소프트박스 / ON AIR | 임시 기구·프레임, 글자는 TMP | 소프트박스 1종 / 사인 프레임 1종 |
| 꺼질 수 있는 방송 LED / EDM LED | 프로토타입은 추가 발광 구역만 제어 | 기존 배경의 밝은 그림을 dark base + emission mask로 분리 |

실시간 Light2D는 기본광과 대표 면광원에 한정한다. 레이저·LED는 공유 머티리얼의 표시 메쉬/스프라이트, 스모그는 ParticleSystem. 처음에는 Bloom 추가 없이 확인한다. Bloom이 이미 있으면 값은 고정하고 조명 자체부터 맞춘다.

additive 빔이 겹칠 때 색이 흰색으로 타버릴 수 있다. 강도/겹침 상한을 두고, 연기와 빔의 화면 점유 면적을 제한한다. 시작 예산은 프로파일링 결과가 아니며, WebGL·모바일에서 프레임 시간/오버드로를 실제 확인한 뒤 확정한다.

## 12. 조명 이후 작업 B에 전달할 것

조명 계획 작성과 실제 구현 완료를 구분한다. 조명을 적용하는 경우 L5까지 기준을 고정한 뒤 B를 진행한다.

1. **B0**: 사용 가능한 조명 큐 목록·대사표·큐시트 레이아웃 확정. 새 연출은 Director의 큐 요청을 통해 연결.
2. **B1**: 힌트 유지 버전으로 관객 관찰 검증부터. 새 마젠타/시안 쇼가 거짓 카드 힌트가 되면 연출 위치/면적을 먼저 수정.
3. **B2~B3**: 체험형 튜토리얼·구체적인 대사·Stage 2 ‘펑!’ 연출. 새 전체화면 플래시를 중복 추가하지 않음.
4. **B4~B5**: 신문 문구/결과 사운드·관객 입퇴장/카드별 움직임. 팬 경로와 바닥등 좌표 공유.
5. **B6**: 맵/카드/시계/SFX 보강. 기존 조명/피버 큐와 타이머 점멸이 겹치지 않게 반복 제한.

이번 문서 작성에서는 게임 런타임 파일, 씬, 프리팹, 아트, 음악을 변경하지 않았다.
