## 실제 설정·연동

- `Main`의 기존 `Rule_FestivalRainShower`에 `RainShowerVFX`를 추가하고 저장했다.
- `AudienceMember.prefab`의 경고 바 두 Renderer에만 `Resources/Effects/AudienceWarningUnlit.mat`을 연결했다.
- 관객 본체와 보스 팬은 기존 Lit 재질을 사용한다. 경고 바의 Unlit 처리를 캐릭터에 전파하지 않는다.
- `TourPrototypeUI`가 기존 `TourRunManager`에 획득 표시 컴포넌트를 한 번 연결한다. 기존 증강 팝업의 `DungGeunMo` 폰트를 재사용한다.
- 새 덱 획득 표시는 `StateChanged` 이후 실제 `addedCards.instanceId`를 확인한다. 저장된 Run 복원·알림 재호출에는 지급/획득 표시를 반복하지 않는다.
- 테스트 스크립트는 `Docs/Verification/VFX`에 있으며 빌드용 런타임 어셈블리 밖에 있다. 테스트용 강제 이벤트·배치 변경은 Play Mode에서만 실행했다.

### 보스 관객 공통 상태

| 기존 게이지 비율 | 공통 상태 |
| --- | --- |
| 0~33% | Calm |
| 33% 초과~66% | Middle |
| 66% 초과 | Excited / Hype |

HP가 다시 오르면 상태도 다시 올라간다. 0%에서도 이 표시 컴포넌트가 승패를 새로 판정하지 않는다.
같은 상태 동안 종족·자리·애니메이션을 매 이벤트마다 초기화하지 않는다.

## 남은 직접 플레이 확인

- 3스테이지 자연 진행 중 소나기 시작/종료, Chill 보호 아치의 가독성.
- 세 카드의 군집 행동을 보고 성향 차이가 즉시 느껴지는지, 기본 관객 수와 최대 관객 수에서 과하지 않은지.
- 보스 정상 예고 → 실제 미션 → 성공/실패 → 복귀의 연출 길이. **BGM 실제 드랍 박자 동기화는 미구현**이며 현재는 미션 시작 큐에 동기화한다.
- 정상 결과 → 증강 → 맵 흐름에서 덱 획득 알림이 맵 조작/다음 대화를 방해하지 않는지.
- WebGL·모바일 실기기 화면/터치/프레임 시간/알파 오버드로우. 이 작업에서 빌드나 실기기 테스트는 하지 않았다.
