## 2. 현재 코드에서 확인한 출발점

- `StageEventNoticeUI`: 미션 아트는 공통 `MissionCueSheetView`를 쓰지만, 위치는 여전히 상단 중앙 / 1000×256이다.
- `BossBattleUI`: 미션은 왼쪽 중단 / 기본 512×384, 두 미션은 한 창에 합쳐 표시한다. 관객 바는 아직 단색 사각형이며 라이벌이 왼쪽이다.
- `TutorialOverlayUI`: 튜토리얼은 왼쪽 중단이지만 자체 가변 크기를 쓴다. **튜토리얼 크기를 무조건 보스 창과 같게 바꾸지 않는다.**
- `AudienceRosterPresenter.Relayout()`: 현재는 같은 간격의 중앙 정렬 격자다. `AudienceMemberActor.SetLayout()`에 재배치 보간이 이미 있다.
- `BossStagePresentation`: `boss_camera.png` 버튼은 이미 클릭/Tab 전환이 가능하다. 위치는 오른쪽 가운데다.
- `BossBattleUI`: 점수 감소는 상단의 작은 숫자 팝업으로 표시된다. `BossDrainApplied.Amount`는 실제로 차감한 값이며, 현재 점수 이하로 제한되어 있다.
- 소나기·관객 보호·대표 카드 군집 행동·보스 드랍 조명/점프는 이미 구현되어 있다. 기존 효과를 중복 추가하지 않는다.

이번 조사는 코드·에셋 및 기존 보고서 대조다. 아직 새 레이아웃의 실제 화면을 검증한 것은 아니다.

### P2. 보스 HUD를 첨부 기획에 맞게 교체

지정 에셋은 모두 `Assets/Sprites/0930_art/`에 있으며 크기는 각각 **202×10**이다.

| 에셋 | 역할 |
| --- | --- |
| `boss_bar_back.png` | 외곽 프레임·빈 바. 가장 위에서 테두리 보존 |
| `boss_bar_me.png` | 왼쪽 우리 관객 / 시안 |
| `boss_bar_boss.png` | 오른쪽 라이벌 관객 / 마젠타 |

- 프레임과 두 채움은 같은 원본 좌표계·같은 비율로 겹친다. 시작 크기는 정수 배율 **606×30(3배)**로 두고 실제 HUD와 대조한다. 가로만 늘려 픽셀을 찌그러뜨리지 않는다.
- 두 채움은 서로 반대쪽에서 같은 경계를 공유하도록 잘라 표시한다. 채움 이미지 자체를 비율별로 압축하지 않는다.
- 초기 배치안은 상단 중앙, 상단 여백 약 54px다. 좌우에 **우리 관객 수 / 라이벌 관객 수**를 표시하고 색만으로 팀을 구분하지 않도록 짧은 팀 표기도 남긴다.
- 실제 값은 `BossFanBalanceChanged`만 사용한다. 현재 단색 바와 달리 **우리 왼쪽 / 라이벌 오른쪽**으로 방향을 뒤집되 룰의 팬 수는 바꾸지 않는다.
- 두 채움의 보간값은 하나의 비율을 공유해 경계 틈·겹침을 방지한다. 0명/전원/합계 0명도 안전하게 표시한다.
- 마젠타·시안 아트의 원색을 유지한다. Revenge는 별도 짧은 태그/테두리 강조로 표시해 팀 색을 섞지 않는다.
- 아래 안내는 **`다음 점수 감소까지 00:15 · -168점`** 같은 형식으로 실제 카운트다운 값을 표시한다. 첨부 이미지의 ‘관객 감소’ 문구는 사용하지 않는다. 현재 규칙은 팬 자체가 아니라 **점수**를 감소시키기 때문이다.
- 우상단 등급/기존 등급 게이지는 별도 HUD다. 쟁탈 바와 연결하거나 F등급 기준으로 채움량을 보정하지 않는다.
- 스프라이트 참조는 기존 보스 컴포넌트의 직렬화 필드로 노출하고 Main에 연결한다. 매 프레임 검색·로드, 에디터 전용 경로 의존은 금지한다.

**카메라 버튼:** 기존 `boss_camera.png`, 클릭·Tab·잠금 동작을 유지하면서 첨부처럼 우하단에 배치한다. 손패 우측 끝·드래그 경로와 겹치지 않게 하고, 우리/라이벌 화면 모두 같은 화면 좌표에 둔다. 레이아웃을 덮어쓰는 `SetPeekLabel()` 경로도 함께 바꾼다. 라벨은 ‘라이벌 무대 보기 / 우리 무대 돌아가기’로 현재 행동을 알린다. 자동 예고 중/ESC 중에는 기존대로 조작하지 못한다.

검증: 우리:라이벌 `0:전원 / 절반:절반 / 전원:0`, 0합계, 팬 이동 연속 발생, Revenge, Pause, 보스 화면 왕복. 프레임 끝의 사선·흰 외곽선이 가려지거나 픽셀이 흐려지지 않아야 한다.

### P3. 관객 간격 / 가림 / 자연스러운 배치

**목표:** 간격만 무작정 늘리는 것이 아니라 관객 얼굴·테두리·말풍선과 입력 대상이 읽히게 한다.

- 기존 `AudienceRosterPresenter` 배치 계산을 확장한다. 별도 관객 시스템이나 실제 관객 데이터 복제는 만들지 않는다.
- 우선 가로·행 간격을 넓히고, 앞·뒷줄을 반 칸 엇갈리게 한다. 작은 고정 오프셋으로 정렬된 군대 같은 인상을 줄인다.
- 오프셋은 관객 ID 기반으로 고정한다. 게임의 공용 난수 상태를 소비하지 않고 매번 재배치할 때 자리가 출렁이지 않게 한다.
- 밴드 몸체, 좌측 미션 패널, 화면 가장자리, 손패의 가림 영역을 기준 화면에서 정한다. 일반 관객은 먼저 얼굴/상체가 이 영역에 겹치지 않도록 후보 자리를 조절한다.
- 원근 크기는 유지하되 뒷줄을 너무 작게 줄이는 방식으로만 해결하지 않는다. 기본·최대 관객 수에서 행 수와 폭을 확인한다.
- 기존 `SetLayout()` 보간·입퇴장·카드 반응 오프셋을 합성한다. 이동·모쉬핏 중 Transform을 별도 트윈으로 덮어쓰지 않는다.
- 라이벌 쪽은 이미 별도 퍼짐과 jitter가 있다. 카메라 왕복에서 문제가 보이는 값만 조정하고 우리 쪽 배치 알고리즘으로 통째 교체하지 않는다.
- 튜토리얼 대상 고정, 스페셜 관객 자리, Hover/길게 누르기 콜라이더·말풍선 추적은 유지한다.

검증: 각 스테이지 기본/최대 인원, 큰 종족, 입퇴장 연속, 모쉬핏·싱어롱 움직임, 보스 쟁탈·카메라 왕복. 사람이 얼굴을 보고 선택 가능한지는 실제 화면으로 판정한다. 자동 bounds 검사만으로 완료 처리하지 않는다.

| **Stage 3 깃발 호응** | 객석 바깥 양쪽에서 보라·아이보리 긴 테이프가 위로 뿜어지고, 큰 천 조각 같은 입자 몇 개가 바깥을 스친다 | 성공 때 양쪽 컨페티 캐논이 한 번 더 크게 터짐. 실패는 남은 테이프가 힘없이 아래로 떨어지고 주황색 큐시트 악센트. 새 깃발 캐릭터 애니메이션은 요구하지 않음 |
| **Stage 4 카메라 큐** | 좌우 장비 위치에서 직사각형 플래시 조각이 짧게 번쩍이고, 큐시트 모서리에서 종이·테이프 조각이 ‘탁’ 튄다. 방송 시작 슬레이트를 치는 느낌 | 진행 중 매 프레임 폭발 없음. 실제 전체 성공 때 큐시트 바깥으로 금색·아이보리 리본이 퍼짐. 실패는 큐시트 아래로 종이 조각이 떨어짐. 카메라 플래시를 연속 스트로브로 만들지 않음 |
| **Stage 4 정전** | **암전 중 입장 발광 파티클 없음.** 기존 조명 소등과 큐시트 자체의 대비로 사건을 전달 | 실제 전력이 복구되어 월드가 다시 보이는 첫 구간에만 장비 주변 짧은 전기 스파크·얇은 연기. 화면을 가르는 번개/지속 발광은 없음. 성공/실패는 별도로 큐시트에서 표시 |
| **관객 이탈 위기** | 관객이 떠나는 방향의 화면 가장자리에서 주황색 짧은 속도선·먼지가 바깥으로 쓸려감. 무대가 관객을 놓치는 느낌 | 실제 붙잡은 결과에만 청록색 안쪽 파동. 실제 이탈한 관객에만 기존 퇴장 효과를 보강. 멀쩡한 관객을 가짜로 사라지게 하지 않음 |
| **관객 지원 / 힙스터 팬 합류** | 기존 관객 입장 위치에서 큰 청록색 음표·별 조각이 분수처럼 솟고, 낮은 파동이 안쪽으로 밀려온다 | 실제 합류 시점에 입구 주변 테이프·먼지를 한 번 방출. 모든 관객에게 각각 폭죽을 붙이지 않음. 기존 입장 이동은 유지 |
| **보스 미션 / 스탠딩석 쟁탈 결과** | 미션 큐시트 바깥에 마젠타·시안 각진 파편이 빠르게 펼쳐짐. 본문 위를 가리지 않음 | 성공은 바깥으로 솟는 작은 캐논, 실패는 아래로 깨져 떨어지는 파편. 기존 드랍 레이저·스모그·점프와 팬 도착 파장을 중복 재생하지 않음 |

‘관객 이탈 / 지원’은 현재 활성화된 스테이지의 기존 이벤트 경로에만 붙인다. 모든 스테이지에 새로 발생시키거나 이벤트 빈도를 바꾸는 기획이 아니다. 보스 결과 버스트는 드랍의 주연 연출보다 짧고 작게 둔다.

#### P4-3. 큰 느낌을 만드는 기준

- **작은 점 수백 개보다 큰 실루엣:** 픽셀 조각, 긴 사각 테이프, 굵은 빗줄기, 음표를 섞는다. 1920×1080 기준 주요 조각의 보이는 길이 16~48px부터 비교한다. 전부 같은 작은 반짝이로 만들지 않는다.
- **크기·속도·방향을 과장:** 처음엔 빠르게 퍼지고 금방 감속한다. 지면 물보라/공중 테이프의 궤적을 구분해 소나기와 축제가 다른 사건처럼 보이게 한다.
- **무대 가장자리가 주 무대:** 컨페티는 바깥에서 위로, 먼지·속도선은 사건 방향으로. 관객 얼굴과 밴드 중앙에는 덩어리나 불투명 연막을 오래 두지 않는다.
- 큐시트 본문·카드·점수·시계·보스 게이지에는 입자를 덮지 않는다. 큐시트 장식 입자는 판 뒤/바깥에서만 보이고 입력을 받지 않는다.
- 픽셀 아트의 또렷한 경계와 제한 팔레트를 유지한다. 큰 부드러운 구체, 전면 Bloom, 무지개 잡색으로 화면을 채우지 않는다. 이벤트 장식색으로 카드 정답 성향을 새로 알려주지 않는다.
- 진동·흔들림을 기본으로 끼워 넣지 않는다. 이번 ‘과장’의 주 수단은 파티클의 모양·운동·공간이다. 광량 증가나 빠른 전면 점멸에 의존하지 않는다.

#### P4-4. 구현 책임 / 에셋 / 부하 계획

- 판정은 기존 Rule, 파티클은 표시 컴포넌트가 담당한다. `StageEventStarted/Resolved`, 위기/지원 전용 이벤트, 실제 보호 적용 알림, 보스의 기존 표시 이벤트를 구독한다. 한글 진행 문자열을 파싱해 성공을 추측하지 않는다.
- 기존 `MissionCueSheetView`에는 입장/결과 표시 연결만 최소 추가한다. 이벤트별 버스트는 표시 전용 컴포넌트에서 재사용하고 새 이벤트 규칙 시스템은 만들지 않는다.
- 소나기는 기존 `RainShowerVFX`의 방출 분포·속도·초기 버스트를 조절한다. 기존 입자 상한 안에서 시작을 강하게 배분하며 비 시스템을 중복 생성하지 않는다.
- 모양은 작은 사각 픽셀·절차적 선/파동, 재사용 가능한 기존 음표 표현을 우선 활용한다. 연기는 기존 `smoke_cloud`, `smoke_soft_puff`, `steam_wispy` 중 실제 화면에 맞는 것을 선택한다. 신규 캐릭터 프레임·대형 이미지 제작을 필수로 두지 않는다.
- 1회 기본 버스트 32~64개, 큰 성공 캐논은 최대 96개, **P4에서 추가한 입자는 동시 생존 128개**를 초기 상한으로 둔다. 기존 비/드랍 등 다른 효과를 포함한 전체 비용은 별도로 측정한다. 이 숫자는 성능 검증 결과가 아니다.
- 입자는 기본 약 0.3~0.9초 생존. UI 버스트·월드 버스트는 초기화 후 재사용하고 충돌 계산·관객별 ParticleSystem·매 프레임 생성/삭제는 피한다.
- 같은 사건의 시작·결과는 각각 한 번만 방출한다. 새 이벤트가 오면 이전 입장 효과는 정리하고 현재 사건을 우선한다. 기존 위기 경고창과 큐시트를 동시에 복제하지 않는다.
- Pause에서 시간·입자를 멈추고, 결과/스테이지 변경/비활성화 때 정리한다. 보스 카메라가 움직이면 월드 입자는 사건 위치에 남고, UI 입자는 UI를 따른다. 화면 전환 때 엉뚱한 쪽에 다시 터뜨리지 않는다.
- 사운드는 기존 SoundLibrary에 연결된 적절한 ID가 있을 때 한 번만 사용한다. 새 음원 제작이나 BGM 변경은 하지 않는다.

#### P4 완료 판정

- 입장 첫 순간만 봐도 소나기 / 축제 / 방송 큐 / 관객 지원을 형태로 구분할 수 있다.
- 시작 버스트가 큰 상태에서도 해야 할 행동·남은 시간·관객 성향·손패가 읽힌다. 1초 뒤에는 차분한 플레이 화면으로 돌아온다.
- 성공이 아닌데 성공 폭죽이 나오는 일이 없다. 정전 중에는 월드 발광이 없고, 기존 보스 드랍과 이중 폭발하지 않는다.
- 이벤트 연속 발생·결과 유지 중 다음 이벤트·Pause·강제 종료·재시작에서 잔상·입자 누적이 없다.
- Fever + 이벤트, 최대 관객 + 이벤트, 보스 카메라 왕복 + 결과를 실제 화면으로 확인한다. 기존과 비교한 프레임 시간/GC/입자 수를 기록하며 WebGL 미검증은 별도 표기한다.

### P5. 보스 점수 감소를 명확하게

현재의 작은 상단 `-숫자`만으로는 **어느 값이 왜 줄었는지** 연결하기 어렵다.

1. 감소 전: 실제 카운트다운 마지막 약 2초에 안내만 짧게 경고색으로 강조한다. 시계 시스템이나 BGM은 건드리지 않는다.
2. 감소 순간: **실제 점수 HUD 옆**에 `-168점` 같은 숫자와 짧은 붉은 악센트를 표시한다. 보스 팬 쪽에는 작은 원인 강조를 넣어 ‘라이벌 관객 → 점수 감소’를 연결한다.
3. 감소 직후: 기본 색·크기로 복구한다. 관객 비율 바는 팬 이동이 있을 때만 변하고, 점수 감소 때문에 팬이 사라지는 연출은 하지 않는다.

- 표시 수치는 `BossDrainApplied.Amount`만 쓴다. 예정 감소량을 실제 차감량으로 표시하지 않는다. 0점에서 Amount=0이면 가짜 손실을 만들지 않는다.
- 기존 상단 감소 팝업과 새 팝업을 동시에 재생하지 않는다. `ScoreUI`는 표시 좌표/색·강조 연결만 최소 확장하고 점수 계산은 소유하지 않는다.
- 카드 득점과 같은 프레임에 발생해도 최종 숫자는 최신 점수여야 한다. 현재 카드 표시용 지연 코루틴이 과거 점수로 되돌리지 않는지 확인한다.
- ESC·보스 컷신의 정지 규칙을 따르며 복귀 후 손실 팝업이 한꺼번에 재생되지 않게 한다.

검증: 잔여 점수보다 큰 예정 감소, 실제 감소 0, 카드 득점과 연속/동시 발생, 팬 0명으로 감소 정지, Pause/결과/재시작. 룰의 점수·팬 수·판정은 수정 전과 같아야 한다.

### P6. 통합 검증 / 인계

- Unity 재컴파일 성공, 검증 시작 이후 Console 새 오류 0.
- 1920×1080 / 1280×720 / 좁은 창에서 미션·쟁탈 바·카메라·손패 겹침과 긴 한글 확인.
- Stage 3·4의 정상 이벤트와 보스 예고→드랍→미션→팬 이동→점수 감소→결과 흐름 확인.
- ESC→옵션→복귀, 결과→증강→맵→다음 공연에서 잔상·입력 차단·이벤트 중복 확인.
- 지난 디스토션 색 유지, 암전, Fever, 보스 드랍 1회, 관객 원색/틴트 전환·공통 상태·점프 복구를 회귀 검사한다.
- 새 효과는 시작 때 생성 후 재사용하고 매 프레임 씬 전체 검색·무한 입자 증가를 금지한다. GC/프레임 비용은 실제 측정한 범위만 보고한다.
- 변경 전후 캡처, 수정 파일, 검증 결과, 남은 직접 조작/모바일/WebGL 확인을 구분해 보고한다. Editor 통과를 WebGL 검증으로 쓰지 않는다.
- 검증용 강제 이벤트·배치는 Play Mode 안에서만 실행한다. 테스트 점수 업로드·배포·임의 커밋은 하지 않는다.
