# 관객 유입·이탈 시스템 작업계획

> 개인별 몰입도(0~100) 개편은 별도 담당자가 `Assets/Scripts/CrowdComposition/` 쪽에서 진행 중.
> 이 작업은 그 작업을 건드리지 않고 **"일반 신규 유입"**과 **"이탈 처리"**만 선행 구현해 두고,
> 몰입도 시스템이 완성되면 몰입도 0 도달 시점에 한 줄만 호출해 이어붙일 수 있게 만든다.
> (관련 시스템: `Assets/Scripts/AudienceLifecycle/`, `Assets/GameJamKit/Core/GameEvents.cs`)

## 기획 요약 (`.myDox/기획안 변경 아이디어 정리.md` 4장 기준)

- 초기 관객 3명, 성향·몰입도(30~50) 무작위로 시작.
- 공연 중 일정 시간마다 확률적으로 신규 관객 유입, 최대 10명.
- 몰입도 0인 관객은 즉시 이탈, 관객 0명이면 즉시 게임오버.
- 유입 판정 주기·확률, 초기/유입 몰입도 범위는 확정 수치가 아니라 밸런스 조정 대상.

## 확정 설계 결정

| 항목 | 결정 |
|---|---|
| 팀원 몰입도 작업과의 관계 | `CrowdComposition/`(프리셋·전환 로직), `Crowd/CrowdMemberView.cs` 는 수정하지 않음. `Crowd/CrowdSpawner.cs` 는 **추가 전용 API**(`SpawnAdditional`/`DespawnAdditional`)만 덧붙였고 기존 프리셋 그리드(`_members`, `BuildReplacements`, `TransitionComposition`) 코드는 건드리지 않음 — 사용자 요청으로 2026-07-25 변경(처음엔 완전 분리로 갔다가, 씬에 관객이 두 세트로 겹쳐 보이는 문제 때문에 기존 스폰 시스템을 재사용하는 쪽으로 재작업) |
| 관객 프리팹 | `CrowdSpawner` 가 이미 갖고 있는 `chillPrefab`/`singalongPrefab`/`moshPrefab` 참조와 `CrowdMemberView.Setup()` API 를 `SpawnAdditional` 내부에서 그대로 재사용 (새 프리팹 참조를 따로 만들지 않음) |
| 배치 방식 | `SpawnAdditional` 로 추가된 관객은 프리셋 그리드(`_members`)와 별개 리스트(`_additionalMembers`)에 들어가며, 프리셋 그리드보다 앞쪽(음의 y)에 별도 줄로 배치되어 시각적으로 겹치지 않음 |
| 인원수 소스 | 지금은 `AudienceInflowSystem` 이 임시 `Dictionary<memberId, view>` 로 자체 관리. 몰입도 시스템 완성 후 그쪽 로스터로 교체 예정(지금 정식 연동 계약은 맺지 않음 — 사용자 결정) |
| 연동 지점 | `AudienceLifecycle.RequestExit(memberId, AudienceExitReason.NaturalDecay)` 한 줄. `memberId` 는 `AudienceMemberSpawned` 이벤트에서 받은 값을 그대로 사용 |
| 이벤트 위치 | 새 이벤트 파일을 만들지 않고 `GameJamKit/Core/GameEvents.cs` 하단 CONTEXT STAGE 섹션에 추가 (킷 컨벤션) |
