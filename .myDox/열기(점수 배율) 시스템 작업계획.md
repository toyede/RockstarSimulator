# 열기(점수 배율) 시스템 작업계획

> 기존 **호응도(Hype)** 게이지를 **점수 배율 "열기"** 로 재활용하고, 카드가 주는
> 임시 기본 점수에 현재 열기 배율을 곱해 **공연 점수**를 무한 누적시키는 작업.
> (관련 시스템: `Assets/Scripts/Hype/`, `Assets/Scripts/Cards/`, `Assets/GameJamKit/Core/GameManager.cs`)

## 기획 요약

- **점수와 열기 분리**
  - 공연 점수: 카드를 낼 때마다 무한 누적. 스테이지 종료 시 클리어 판정(후속 작업).
  - 열기: 기존 호응도 게이지 재활용. 시간 지나면 감소, 높을수록 점수 배율↑, 실수하면 크게 하락.
- **배율 테이블**: 낮음 ×1 / 중간 ×2 / 높음 ×3 / MAX ×5

## 확정 설계 결정

| 항목 | 결정 |
|---|---|
| 열기 0 도달 | 게임오버 제거. 배율 하한 ×1로만 작동(실패 아님) |
| 열기 MAX(100) | 앙코르 완전 제거 — 70 리셋·감소정지·MAX 추가 드로우 전부 제거. 100에 머물러 ×5 지속 |
| 이번 범위 | 배율 + 점수만. 스테이지 종료/클리어/등급은 후속 |
| 네이밍 | UI 표시만 "열기". 내부 코드는 `Hype`/`HypeSystem` 유지 |

## 팀원 카드 작업과의 관계

- 팀원 커밋 `384b652`("카드 개수")가 이미 머지됨 → 그 위에 얹으므로 머지-텍스트 충돌 없음.
- 팀원은 `HypeSystem`/`HypeConfig`/`GameEvents` 미접촉 → 열기 작업 무충돌.
- **6단계(앙코르 추가 드로우 훅 제거)** 만 팀원 파일(`CardSystem`)과 겹침 → 별도 커밋 + 팀원 공지 후 진행.
